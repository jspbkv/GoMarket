# GoMarket

Минималистичная площадка объявлений о товарах и их обмене в Кыргызстане. Оплата и договорённости происходят напрямую между людьми — сайт не принимает платежи и не организует сделки.

## Запуск

Нужны Node.js 20 или новее и npm.

```powershell
npm install
npm run dev
```

Откройте показанный Vite адрес (обычно `http://localhost:5173`). GoMarket работает только с подключённым Supabase: если проект ещё не настроен, приложение покажет инструкцию и не будет подставлять тестовые товары или сохранять публикации локально.

Для локальной production-сборки и её предпросмотра:

```powershell
npm run build
npm run preview
```

## Публикация на GitHub Pages и домен gomarket.pp.ua

Сайт собирается и публикуется GitHub Actions workflow-файлом `.github/workflows/deploy.yml`. Домен `gomarket.pp.ua` включается в сборку через `public/CNAME`.

1. Создайте GitHub-репозиторий и отправьте в него файлы проекта. Убедитесь, что рабочая ветка называется `main`.
2. В **Settings → Secrets and variables → Actions → New repository secret** добавьте:
   - `VITE_SUPABASE_URL` — URL проекта Supabase;
   - `VITE_SUPABASE_ANON_KEY` — публичный publishable/anon key Supabase.

   Vite встраивает эти значения в клиентскую сборку, поэтому они доступны посетителям сайта. Не используйте `service_role` или другие секретные серверные ключи.
3. В **Settings → Pages** выберите источник **GitHub Actions**. Отправьте изменения в `main` либо запустите workflow вручную во вкладке **Actions**. После успешной сборки GitHub Pages опубликует сайт.
4. В настройках домена на nic.ua задайте DNS-записи для корневого домена:

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |

   Удалите конфликтующие старые A/AAAA-записи для `@`, если они есть. DNS может обновляться некоторое время.
5. Когда DNS-записи применятся, в **Settings → Pages → Custom domain** укажите `gomarket.pp.ua` и сохраните. Дождитесь проверки DNS, затем включите **Enforce HTTPS**. Файл `public/CNAME` сохраняет домен при последующих деплоях.
6. В Supabase откройте **Authentication → URL Configuration**: установите **Site URL** в `https://gomarket.pp.ua`, а в **Redirect URLs** добавьте `https://gomarket.pp.ua/**`. Оставьте разрешённый адрес локальной разработки, если он ещё нужен. Google OAuth callback по-прежнему должен указывать на callback URL Supabase, указанный в настройках провайдера.

Используется корневой кастомный домен, поэтому сайт публикуется по адресу `https://gomarket.pp.ua/`. DNS для `www.gomarket.pp.ua` отдельно не настраивается.

## Подключение Supabase и Google

1. Создайте проект Supabase и в **SQL Editor** выполните `supabase/schema.sql`. Скрипт создаёт таблицы, индексы, политики RLS, RPC для жалоб и публичное хранилище фотографий с ограниченным размером и типами файлов. После изменений схемы повторно запускайте этот файл: он безопасно обновит ограничения статусов объявлений и политики доступа.
2. В **Authentication → Providers** включите Google OAuth и укажите Google OAuth client ID и secret. В настройках OAuth-клиента Google добавьте callback URI Supabase в формате `https://<project-ref>.supabase.co/auth/v1/callback`.
3. В **Authentication → URL Configuration** задайте адрес сайта в Site URL и добавьте адрес локальной разработки в Redirect URLs, например `http://localhost:5173/**`. Для опубликованного сайта добавьте его origin и разрешённые redirect URL.
4. Скопируйте `.env.example` в `.env.local` и укажите значения из **Project Settings → API**:

   ```dotenv
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_ANON_KEY=<publishable-or-anon-key>
   ```

5. Перезапустите `npm run dev`. При наличии обеих переменных приложение использует Supabase и вход через Google; пользовательское содержимое и фотографии доступны публично согласно настройкам площадки. Все операции записи выполняются только для авторизованного пользователя и защищены политиками RLS.

Никогда не помещайте `service_role` или другие секретные ключи в клиентский `.env`: все `VITE_*` переменные попадут в браузерный bundle. Используйте только публичный ключ проекта, включите Google OAuth и проверьте RLS-политики перед публикацией. Старые данные, сохранённые только в браузере, не переносятся в Supabase и удаляются при запуске новой версии.

## Возможности MVP

- Поиск, категория, область, город, диапазон цены и отметка «можно обменять».
- Публикация, редактирование и удаление собственных товаров; в профиле в блоке «Управление объявлениями» можно менять статус, редактировать и сохранять объявление или удалить его. Статусы также доступны в разделе «Мои объявления»; «Продано» остаётся в общей ленте с явной отметкой и без контактов, «Скрыто» видно только владельцу. Владелец может вернуть любое своё объявление в активные.
- До трёх фотографий JPG/PNG/WebP, до 2 МБ каждая, с автокаруселью в карточке и просмотре товара; дата публикации доступна в карточке и деталях.
- Страница товара с контактами продавца, звонком и переходом в WhatsApp.
- Избранные товары с сохранением для вошедшего пользователя; в профиле доступны список избранного, удаление из него, количество своих объявлений и рекламных публикаций, смена языка/темы и выход из аккаунта. Избранное хранится в отдельной таблице Supabase с доступом только владельца.
- Бесплатные рекламные публикации от пользователей с явной пометкой «Реклама», ссылкой и контактом; к каждой можно добавить одну фотографию JPG/PNG/WebP до 2 МБ.
- Жалобы на товары и рекламу; повторные жалобы от трёх разных авторизованных пользователей автоматически скрывают публикацию.
- Стартовый splash screen до первой загрузки и скелетоны при обновлении, состояния пустого результата и ошибки.
- Строгая монохромная светлая/тёмная тема; режим «Система» следует настройке оформления устройства. Тема сохраняется в браузере.
- Переключение интерфейса между русским, кыргызским и английским языками; выбранный язык сохраняется в браузере.
- Необязательные тихие звуки интерфейса: короткий щелчок при нажатии и сигнал уведомления. Отключены по умолчанию; выбор сохраняется локально в браузере и доступен в меню и профиле.
- На небольших экранах — компактное меню с профилем, языком и темой; раскрываемые фильтры и сортировка.
- Адаптивная вёрстка, клавиатурная навигация и уважение настройки уменьшенного движения; фон не прокручивается при открытых меню и диалогах.

## География

В выборе региона есть все семь областей Кыргызстана, а Бишкек и Ош представлены отдельно как города республиканского значения. Для каждой области указаны основные города. Это начальный справочник, а не исчерпывающий реестр сёл и населённых пунктов; список можно расширить по проверенному официальному источнику до запуска в масштабе.

## Практические рекомендации перед публичным запуском

- До продвижения рекламы добавьте доступную модерацию, обработку апелляций и контакты поддержки: автоматическое скрытие по жалобам — только базовая защита, а не полноценная модерация.
- Соберите список городов и региональных названий из официального источника, затем добавьте ввод населённого пункта, чтобы не исключать небольшие города и сёла.
- В интерфейсе есть информационные черновики правил и описания данных; до запуска владелец должен указать оператора и контакт поддержки, утвердить сроки хранения и удаления данных, а документы проверить с профильным специалистом. Телефоны, контакты, ссылки и фото публикаций публичны.
- Настройте резервное копирование Supabase, мониторинг ошибок, лимиты запросов и защиту от спама до масштабирования.
- После проверки спроса измерьте пользу рекламной ленты и только потом решайте, нужна ли платная реклама, верификация продавцов или дополнительные инструменты. В текущем MVP реклама бесплатная, а сделки остаются вне платформы.
